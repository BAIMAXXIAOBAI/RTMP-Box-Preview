RTMP Box Preview 是一款免费使用的 Android 局域网视频工具。接收支持 RTMP 推流的智能眼镜、相机、OBS 等发送端，在手机或平板上看画面、听声音、保存录像，也可以把当前输入主动转发给另一个接收端。

> 仅在可信 Wi-Fi 或热点中使用。应用接收一路 RTMP，不提供浏览器观看或多人拉流分发。

## ✨ 能做什么

| 功能       | 说明                                          |
| -------- | ------------------------------------------- |
| 🎬 实时画面  | H.264 / AVC、H.265 / HEVC 硬件解码，双击全屏，适配横竖屏    |
| 🔊 预览声音  | 播放 AAC 音频，独立开关和本机播放音量，不影响录制与转发              |
| 💾 本地录像  | FLV 可选约每 5 分钟分片；MP4 正常情况下连续保存为一个文件，均不重新编码   |
| ⏪ 预录制    | 提前开启后缓存最多约 3 分钟，开始录制时带上可用历史画面               |
| 🔁 主动转发  | 单目标发送：面向 OBS 的 SRT / MPEG-TS，或自定义完整 RTMP 地址 |
| 🧩 组件首页  | 13 类组件，自由添加、移除、拖拽排序、调整尺寸，选择概览 / 标准 / 详细视图   |
| 📊 专业监看  | 输入与解码帧率、码率趋势、音频电平、录制状态、存储估算和最近事件            |
| 🌗 外观与适配 | 日间、夜间、跟随系统；手机和平板布局，横竖屏分别记住排列                |

## 🚀 快速开始

1. 让接收设备与推流设备接入可互通的 Wi-Fi 或热点。
2. 打开应用，确认显示“等待推流”；接收已停止时，在“接收控制”中启动。
3. 在“连接与地址”组件复制对应网络的地址，填入推流端并开始推流。
4. 开启预览，按需播放声音；选择 FLV 或 MP4，点击“开始录制”。

地址格式：

```text
rtmp://<接收设备的局域网IP>:1935/live/stream
```

推流软件要求分开填写时：

```text
服务器地址：rtmp://<接收设备的局域网IP>:1935/live
串流密钥：stream
```

切换 Wi-Fi 或热点后，请刷新地址。相同网络名称不一定代表设备可互通，热点隔离或防火墙也可能阻止连接。

## 💾 录像与预录制

| 选择  | 保存方式                                |
| --- | ----------------------------------- |
| FLV | 默认约每 5 分钟在下一个视频关键帧另存文件；录制前可关闭定时分片   |
| MP4 | 正常情况下保存为一个连续文件，内部片段属于写入结构，不等于拆成多个文件 |

录像默认保存到：

```text
Movies/RtmpBoxPreview
```

停止录制后等待保存完成。部分相册不显示 FLV，可通过文件管理器查找，并使用兼容相应容器和编码的播放器打开。

**预录制需要提前开启。** 有输入后才开始缓存，约 3 分钟是目标窗口，实际时长受码率、容量和输入连续性影响。

- 录制 MP4：可用历史与后续实时录像写入同一个文件。
- 录制 FLV：历史另存为 MP4，后续正式录像保存为 FLV。
- 格式变化、断流重连或媒体缺口可能触发安全分段；新连接会重新积累历史。

MP4 使用分片写入结构，意外中断时可能保留已完成部分，但两种格式都不能保证断电、强制结束或存储故障后录像完整。重要内容请及时备份。

## 🧩 按自己的习惯组合首页

**右上角调节图标 → 编辑首页 → 顶部 ＋ → 选择组件 → 完成添加 → 顶部保存。**

拖动手柄调整位置，通过卡片菜单修改信息视图与尺寸。小 / 中 / 大代表信息量，字体大小跟随系统设置。外观与布局预设也在“首页设置”中。

移除组件只隐藏卡片，不会停止接收、录制、预录制或转发。请在对应组件中关闭功能；录制卡隐藏时，“首页设置”仍提供停止录制入口。

## 🔁 把当前画面转发出去

先添加“主动转发”组件，再配置一个目标并手动开始发送：

- **OBS**：填写电脑的局域网 IPv4 和端口，电脑端配置 SRT listener 接收，输入格式为 MPEG-TS，并允许对应 UDP 端口。
- **自定义 RTMP**：粘贴接收端提供的完整推流地址，按原地址保存和转发，不自动补写端口或路径；也可以填写另一台 RTMP Box Preview 的接收地址。

转发沿用输入编码、分辨率和码率，不进行转码。只发送当前输入，不发送历史缓存、已有录像或手机界面；接收端必须兼容输入编码。目标接收画面仍需在对端确认，应用显示“正在发送”只表示本机写出有进展。OBS 等组合仍需更多端到端实机验证。

## 📱 兼容要求与使用范围

- 兼容 **Android 8.1 及以上、64 位 ARM** 手机和平板，仅提供 `arm64-v8a` 安装包，不支持 32 位系统或 x86。
- 预览需要设备兼容对应的硬件解码规格，尤其是 HEVC 的分辨率、Profile 与 Level。
- 已在 MI 8（Android 8.1）及 Android 15 手机、平板进行分项兼容验证，各批次覆盖范围不同，不代表所有设备和输入规格均已验证。
- 单路 RTMP 输入、单目标主动转发；不支持 RTMPS、SRT 输入、AV1、非 AAC 音频、浏览器观看或多人拉流分发。
- 转发目标限可信局域网 IPv4，不支持公网、域名、账号密码或 URL 查询参数。RTMP 无鉴权且未加密，SRT 转发未启用加密，请勿映射到公网或形成循环转发。

前台服务与保活机制用于维持后台接收，但系统和厂商省电策略仍可能中断任务。按需允许通知和后台运行；Android 8.1 / 9 录像需要存储权限。不用时请停止接收，持续预览、预录制和写盘会增加耗电与温升。
